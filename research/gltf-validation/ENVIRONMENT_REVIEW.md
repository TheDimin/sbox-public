# HDR environment capture proposal

The current public corpus capture creates directional lights and a fixed exposure, but no environment probe. This cannot validate the reviewed reflective spheres. `SceneCubemap` holds a cubemap and calculates radiance/normalization spherical harmonics; a picture used only as a background is not a substitute. The fixture in `fixtures/environment/` retains the 1K CC0 Artist Workshop HDRI named in the pinned AttenuationTest README. The other reviewed reference images do not establish that same environment. Current Babylon Sandbox source names a default environment and rotation, but the reference screenshot's version and settings remain unknown.

## Coordinator sequence and acceptance

1. Mount/import the fixture into the actual editor's resource namespace, preserving the original bytes and recording resource/compiler identity. The adjacent CUBE/BC6H/GGX vtex is a proposal based on shipped examples, not a verified importer contract. Execute `../../engine/Tools/Gltf/editor/editor_environment_ibl_probe.csx` only after the compiled resource resolves at its stated path. A pass means only a valid six-face texture with mips and a retained SceneCubemap; it does not prove orientation, HDR radiance, proper mip convolution, or pixels.
2. Use one public `Model.Load` CompareMetallic case with the same fixed camera, exposure, source material, black background, and no directional lights. Compare no environment, black environment, and Artist Workshop. Record the resource and source hashes, compiled format and mip count, cubemap transform/bounds, actual custom-object flags, callback errors, geometry submission, and unchanged camera/producer identities. Both negative controls must stay dark and the real environment must measurably change the metallic foreground, with recognizable reflections visible to a human. If not, investigate clustered environment binding and custom-object flags; do not substitute a background image, point light, or a diagnostic material and report IBL as working.
3. Compare reflective and rough surfaces at several roughnesses and observe a stable environment as camera moves. Check source-to-cubemap orientation with distinctive features, HDR range and mip response independently. Use an isolated named setup rather than changing all recipes; keep existing approved captures as regression controls.
4. Only after the IBL control passes, capture a bounded exposure/intensity sweep for AttenuationTest, IridescenceSuzanne and MetalRoughSpheres at fixed camera and presentation. Select a readable setting from actual unedited captures for user review, recording this as an inferred presentation rather than a numeric match to undocumented source exposure. Transmission and other unsupported material features remain separate failures even if lighting improves.

## Proposed integration boundary for review

Add an explicit opt-in environment recipe with the compiled texture resource, source/compiled hashes, rotation, tint and finite covering bounds; reject unavailable, invalid or non-cubemap inputs rather than silently substituting an unrelated texture. Create and dispose a `SceneCubemap` alongside the existing owned directional lights. Record its actual applied properties in `presentationApplied`, including the real texture identity and completeness; preserve the existing background independently. Retain the present capture behavior for recipes without the new field and for all 18 user-approved controls. Any optional visible sky must use the same real HDR source, with matched rotation, and be recorded separately. Native positive/negative controls must establish whether the public custom object's environment flags or another binding change is needed before setting them in production.

No editor test, texture compilation, render, exposure selection or user approval has been performed by this document or the static fixture checks.

The opt-in capture request uses `presentation.environment` with `type: "cubemap"`, mounted resource-relative `texturePath`, absolute `sourcePath` and `compiledPath`, their exact lowercase `sourceSha256` and `compiledSha256`, `sizeInches`, `yawDegrees`, and optional linear `tint` RGBA. The source and compiled paths are independently hashed, but the current capture cannot establish that the resource loader chose the specified compiled file; the coordinator must check the actual mount and resource resolution. Bounds are centered on the model and must exceed twice its largest extent. A missing or invalid requested cubemap fails the capture; an absent or legacy environment type keeps the previous no-probe behavior. The probe and texture are scene-owned/borrowed respectively, and cleanup deletes the probe before destroying the private scene.

For import, make the fixture's repository-relative resource path available under an editor-owned asset mount and compile the vtex using that editor's AssetSystem. The source path inside the vtex must resolve to the fixture HDR on the same mount. Verify the actual compiled file path and hash before constructing an isolated request. If the compiler rejects CUBE with GGX or HDR input, preserve that failure and adapt the vtex with evidence rather than assuming import success. Do not write the fixture or results into the current Run output or regenerate canonical recipes for this probe.
