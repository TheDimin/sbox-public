# Selected-material batch and generated cache

The selected-packet transaction now prepares only currently requested, missing
lit materials, registers their texture resources together, and invalidates the
native database once. It retains existing packet and per-resource leases and
releases staged resources on success or failure. The generated prepared-byte
cache is content-addressed and disk-backed, with source hash, MIME, transfer,
mip requirement and producer/codec identity in its key. Reads validate the
payload digest; corrupt entries are regenerated. It retains no decoded cache
in managed memory after the current preparation transaction. Native codec
identity failures or unsupported Basis inputs bypass the cache. The cache has a
2 GiB admission limit and stops publishing new entries when full. MVID-based
producer identity is conservative and can invalidate entries after unrelated
engine rebuilds. Original textures and the pinned model are unchanged.

The guarded cold-first benchmark used the original embedded-image
`glTF-Binary` SHA256 `bd7133b4b322aae97c589b8839dae8155ad2546acb35ae32a127e722a959d007`,
Engine MVID `5832b742...`, and a fresh source model alias on each run. The
first run had 33 cache misses, 10 hits and wrote 738,199,704 generated bytes;
the next two had 43 hits and zero misses. No cache was cleared. The timer starts
immediately before public `Model.Load`; it includes a complete base-mip GPU
readback for every one of the 33 distinct selected textures and a subsequent
nonempty captured frame. Mount/setup and cleanup are outside that timer.

## Fresh-alias database lookup follow-up

On the earlier performance producer, three freshly registered GUID aliases
loaded without a database invalidation and all twelve mips matched their
prepared bytes; a released texture followed by a fresh alias with different
content also matched. A deliberately queried missing alias remained missing
after registration without invalidation, showing why this cannot be generalized
to previously exposed names. Receipt
`Temp/gltf-validation/direct-gpu/texture-benchmark/no-invalidation-stage/probe/probe-01-editor_direct_gpu_tests/receipt-01.json`,
SHA256 `cabd6f92148347120d0d5149b11ccb86a0430e42c57841273e4fd6469c12f324`.

The follow-up cache implementation tries only its private newly minted aliases
without invalidation. A null or error result gets a new alias and one explicit
database invalidation before retry; previously successful textures remain
owned and a failed batch rolls back. The actual editor fault test passed for
mixed hits, independently disposed duplicate leases, partial registration and
load failures, successful retry with a distinct alias, failed retry cleanup,
and all twelve GPU mips of a texture loaded before the forced fallback
invalidation. Receipt
`Temp/gltf-validation/direct-gpu/texture-benchmark/fresh-fallback-current/probe/probe-01-editor_direct_gpu_tests/receipt-01.json`,
SHA256 `46ea67cc3a358ec5a87be8bcbc31f3305f71371fdae2a2ff4313eebca2748086`.
The non-null borrowed-error sentinel branch remains unexecuted. A separate
explicit recovery test for a previously missing alias and current source and
canonical compiled render checks remain pending.

The subsequent single prepared-cache comparison on the fresh-alias producer
explicitly prepared the cache first. That prewarm took 11,647.44 ms, with 30
misses, 13 hits and 671,090,640 bytes written; the immediately preceding fault
test had already prepared three textures. The warm load then recorded 43 hits,
zero misses: `Model.Load` 317.54 ms, materials 3,065.96 ms, and first submitted
frame 3,764.45 ms. Five pixels differed from the full-resident frame at
4,794.76 ms, so the first submitted frame is not established as correct. The
preceding producer's comparable single warm diagnostic recorded 4,763.24 ms
materials and 5,399.57 ms to first submitted frame with the same five-pixel
difference. These non-interleaved runs use different engine builds and are not
an isolated randomized comparison. Neither establishes the requested two-second
correct-frame target.

Separate prepared-resource stages on the fresh-alias producer measured
preparation 1,160.42 ms, the first all-resource batch 1,544.68 ms, repeated
per-material acquisitions 807.61 ms, and a separate full role-vector SHA pass
807.50 ms. Receipt
`Temp/gltf-validation/direct-gpu/texture-benchmark/fresh-warm-profile/probe/probe-01-editor_direct_gpu_tests/receipt-01.json`,

Following a separate guard refusal, the existing editor's supported plain

resource counts remained Texture 251, Model 151 and Material 20. The tool's
video-memory result was 0 MiB with no budget and does not establish VRAM use.
Host available memory was 7,321,661,440→7,311,106,048 bytes during the action,
so no immediate host-headroom improvement is attributed to collection. Receipt
`Temp/gltf-validation/direct-gpu/texture-benchmark/editor-gc-once.json`, SHA256
`cb214a238bc59363967b72eda595d451d7b903632ea623d12a7d4b9d54018862`.
No finalizer wait, forced compaction, resource-cache clear or system setting
change was performed.

To make room within the unchanged 2 GiB generated-cache cap, a separately
reviewed, content-derived manifest identified 33 ABeautifulGame entries from
the superseded producer. Under the cache's publication lock and the host guard,
each listed file was rechecked for canonical parent, owner, no symlink,
inode, modification time, length, cache header and complete payload hash.
All 33 passed and were deleted; none were skipped. Exactly 738,201,288 bytes
were reclaimed, leaving 1,408,945,328 bytes of other generated cache data.
