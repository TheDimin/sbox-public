## Running focused tests

Freeze source, producer dependencies, expected cases and assertions before execution. For native tests and captures, hold `/tmp/codex-sbox-gltf-model-tests.lock` across guarded admission, request copy, execution and receipt review. Copy the frozen selection into `Temp/gltf-validation/direct-gpu/current-tests.json` inside the guarded child immediately before dispatch. Do not edit a freeze during execution; corrections require a new freeze and retain the failure. Do not silently modify an older pure-suite manifest to admit new tests.

[`engine/Tools/Gltf/editor/editor_direct_gpu_tests.csx`](../../../engine/Tools/Gltf/editor/editor_direct_gpu_tests.csx) defines the version 1 selection schema. It checks loaded Engine/Gltf and test framework identities, helper source hashes and explicit suite types/counts; it compiles helpers against loaded producers and rejects replacement producer namespaces. It supports primitive MSTest DataRows and static result arrays, with optional public static setup and `$checkout` expansion. Declared totals are counted before compilation: compilation or setup failures leave cases incomplete. Inspect the receipt and cleanup errors; successful transport alone is not a pass. If using archived helper inputs, follow the runner's `snapshot_path` restrictions and verify its source/manifest identities.

Use independent source or numeric oracles and relevant positive, empty, deletion and negative controls. Report planned, passed, failed and incomplete cases with actual producer, helper, shader and artifact identities. GPU readback, rendered comparison, public API integration and wall-clock animation are separate evidence. Follow [native capture controls](../NATIVE_CAPTURE_CONTROLS.md) for camera and presentation; user review determines source-versus-engine appearance.

## Corpus comparison and evidence

[`Run`](../../../engine/Tools/Gltf/scripts/Run) drives the pinned corpus through public `Model.Load` and ordinary/skinned renderers using recorded reference recipes. `Temp/gltf-validation/current/run.json` and `Temp/gltf-validation/current/website` are run artifacts, not proof of current producer or live state; inspect actual timestamps, identities and receipts before use. [Capture review queue](../CAPTURE_REVIEW_QUEUE.md) and [feature status](../FEATURE_STATUS.md) provide review and feature context. Do not relabel older captures with a newer producer. The site presents the current run, without falling back to earlier results.

Historical evidence illustrates why run results must remain scoped:

- A corpus sweep recorded 83 captures and 117 ordinary load errors among 200 completed variants; 137 of 337 were blocked after native crashes. Captures were not visual approvals. A later bounded batch recorded 22 captures, with two BoxVertexColors images held as black; it superseded that batch rather than proving the whole corpus.
- BrainStem, MetalRoughSpheresNoTextures and SimpleInstancing runs encountered native SIGSEGVs; recorded top frames involved `libmaterialsystem2.so` and, in the earlier sweep, `libengine2.so`. The cause was unproven and contemporaneous checks found no OOM. Investigate actual failure evidence and current state before retrying; do not enter a blind restart loop.
- Selected historical public proofs include SimpleSkin source/compiled poses, BoxTextured forms and AnimatedMorphCube stills and cadence; they do not establish complete material or corpus parity. A pure 816-case pass plus three codec preflights is CPU/data evidence. Earlier producer identities and exact scope must stay attached to these results; see [Model.Load integration](MODEL_LOAD_INTEGRATION.md) and feature status.
