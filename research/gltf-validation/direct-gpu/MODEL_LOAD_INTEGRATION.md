# Required managed Model.Load integration

Status, 6 November 2026: the bounded managed public path is implemented and installed, with selected actual public API/render proofs. Stage `c5c0fe3da02d46efaca6decd71760d42` uses Engine `2c054bba-c0fa-43b5-a3a2-39a34ff7577f` and glTF `c869761c-5b80-462d-982a-bc3a688e57b6`. Complete model/API parity remains required; a helper-only loader or native placeholder is still unacceptable.

`Model.Load/LoadAsync` dispatch explicit glTF paths to `GltfModelLoader`, which prepares `GltfManagedModelResource` and constructs a `Model` through the internal managed constructor with null native `IModel`. CPU metadata precedes lazy GPU/material realization. Ordinary `ModelRenderer` and the managed `SkinnedModelRenderer` adapter own real `GltfGpuInstance`/`SceneCustomObject` presentation. Managed skeleton/sequence/logical-morph read models are present for their tested scopes; existing vmdl native branches remain separate. This is the current path, not the native-mesh construction described in the historical audit below.

Accepted scopes include c5 SimpleSkin's 57 public cases plus three handle controls and four source/compiled GPU/reference poses (`e9a3bc6a…`, `2c7a40a3…`); AnimatedMorphCube's reader/public/manual-clock cases, six source/compiled stills and source-form two-loop cadence (`66ac4a30…`, `98e4f877…`, `165598de…`); and all six BoxTextured source/derived-compiled forms (`46d4c955…`, `c97866b3…`). The current pure816/three-codec-preflight pass (`e8f0cbc4…`) is CPU/data evidence. See [FEATURE_STATUS](../FEATURE_STATUS.md) and [execution evidence](EXECUTION.md) for exact receipts, mixed-batch failures and limits.

Remaining gates include full accessor/transform/deformation GPU matrices; broader authored skeleton/bone-object APIs and tiny finite public TRS regressions; complete material/variant/override precedence; graphs, native scene queries, physics, LODs/bodygroups/attachments/game data; broader editing/reimport; portable GPU-ready compilation and matched vmdl performance; and Windows. Public resources now retain valid empty or unselected scenes, expose authored/default/selected scene metadata and allow explicit `Model.Load(path, sceneIndex)` selection; rendering an unselected resource reports the missing selection. Focused source/compiled identity and grouped reimport controls passed on 01459/e12, respectively. These do not establish persistent GUID/hash cold loads or complete publication.

## Historical coupling audit and original proposal

The following audit and proposed acceptance matrix predate the fee5/c5 managed integration. They are retained as proposal history, not statements that the current loader still constructs native meshes or that public loading is unimplemented. Items proved in the scopes above are no longer wholly pending; all unproved portions remain requirements.

At audit time, the native-model prototype had these dependencies:

| Surface | Historical coupling | Originally required managed branch |
| --- | --- | --- |
| `Resources/Model/Model.Load.cs` | Explicit glTF path enters `GltfModelLoader`, which builds native meshes/model; GUID-only branch calls native resource loading | Same public `Model.Load/LoadAsync` returns a `Model` with a managed backend; logical source/compiled path and registered GUID resolve consistently |
| `Resources/Model/Model.cs` | Sealed class; constructor rejects null `IModel`, weak registration uses native GUID; validity/error/mesh count/LOD/base-model getters call native | A second internal constructor stores an explicit managed backend and stable resource identity; each corresponding getter delegates to that backend before the unchanged native branch |
| `Model.Bounds.cs`, `Model.Material.cs`, `Model.Skeleton.cs`, `Model.Morphs.cs`, sequence/animation, parts/attachments/data/physics/hitbox partials | Most accessors are views over `IModel` or native data handles | Managed read models for glTF-backed data, preserving public types and names. Empty optional data has established empty semantics; unimplemented authored features remain acceptance failures, never fabricated native defaults |
| `Scene/Components/Render/ModelRenderer.cs` | Setter immediately calls `field.native.GetNumMeshGroups`; enable creates native-model scene object; `UpdateObject` assigns `SceneObject.Model`, native masks/material groups | Explicit backend dispatch before these dereferences; create/update/dispose a direct GPU instance through an internal renderer adapter. Existing `SceneObject` surface can expose its real `SceneCustomObject`, without assigning a native model |
| `ModelRenderer.Materials.cs` | Per-slot overrides call `SceneObject.native.SetMaterialOverrideByIndex` | Renderer adapter resolves asset/default, material group/variant and component overrides through measured existing precedence. Each instance owns its override state; materials remain shared leases |
| `SkinnedModelRenderer` and its sequence/bone/morph/graph partials | SceneModel-based animation state, native graph evaluation, native controllers and bone object reads | Common internal pose/sequence backend consumed by existing public properties; apply exactly one `GltfPose` revision to palette/morphs. Keep native graph integration as an explicit investigated interface question rather than substituting native models |
| `Systems/SceneSystem/SceneObject` and scene queries | Native model-bound geometry readback, traces, physics and bounds do not understand arbitrary GPU buffers | Audit each used query. Bounds/collision/trace need explicit managed data or useful native shape services. No assumption that a custom draw automatically adds collision, selection or model trace support |
| Resource lifetime/hot reload | Native cache keyed by binding address, native strong handles and model reload views | Managed cache keyed by logical resource identity, independent backend/instance leases, main-thread queued GPU release and safe generation replacement. Retain proven native-cache lifetime fix unchanged for vmdl |

A bounded internal boundary can be a nullable `ManagedModelBackend` field in the sealed `Model`, plus an internal renderer-instance interface. This does not require unsealing or replacing the public type. The resource backend owns immutable document/compiled metadata, input GPU buffers, material leases and read models; the renderer instance owns pose clocks, outputs, palette/morph state, overrides and its custom scene object. Public APIs dispatch on the actual backend. Do not route native methods a zero handle and hope for defaults.

First implementation slice, after direct GPU triangle and model oracle proof: public load/validity/bounds/material count, basic `ModelRenderer` creation and transform/lifetime dispatch. The corresponding first end-to-end test must load both source glTF and portable `.glb_c` through **public `Model.Load`**, assign to ordinary `ModelRenderer` components, render the actual buffer path, and assert:

1. Managed backend identity is present and `Model.native` is null; no loader or draw helper creates native `Model`/`Mesh`/model builders.
2. `IsValid`, `IsError`, mesh/material counts, bounds and resource identity are correct; repeated loads share immutable buffers while separate renderer instances retain independent transforms and material overrides.
3. Runtime vertex descriptors read adversarial accessor offsets/strides and normalized formats correctly; raw GPU readback agrees with independent source arithmetic and final images agree with independent literal geometry controls.
4. Positive and reflected full-affine placement render with the correct front face; exact zero scale is finite/collapsed and recovers on a later pose.
5. Disable/destroy/model replacement removes draw callbacks and releases instance buffers once. A retained second instance remains valid. Final release drops asset-owned buffers/material leases; cold load works again.
6. The same test scene contains an existing vmdl control. Its native model branch, materials, validity and before/after pixels remain unchanged.
7. Compiled-only mounted load resolves logical `.glb` to `.glb_c`, source dependencies are packaged correctly, and required/optional extension diagnostics remain distinct.

This first slice is not full model parity. Skeleton public identity/parents/bind transforms, all sequence/clock controls, logical morph APIs/manual overrides, graph references, per-slot/per-variant override behavior, bodygroups/LOD/attachments/game data, physics/joints/ragdolls/hitboxes, editor selection/preview/undo/save/reimport and native query integration still require their own tests and real implementation. Current prototype CPU bounds calculation and duplicate read/packing are diagnostic scaffolding; load-time/runtime-memory parity versus compiled vmdl is unproven and must be measured before accepting the final architecture. Windows remains a separate completion gate after Linux evidence.
