## Audited integration touchpoints

No production edits were made by this model owner.

- `engine/Sandbox.Engine/Resources/Model/Model.cs`: the sealed resource's only
  constructor rejects a null native model, `IsValid`/`IsError` are native-only,
  and destruction tracks native mesh/material ownership. A real managed backend
  needs explicit resource state, metadata and ordered disposal delegation.
- `Model.Load.cs` already dispatches explicit glTF paths to `GltfModelLoader`;
  that loader still builds native meshes/models. This branch must select the
  actual managed resource backend, preserving the vmdl branch.
- `Model.Bounds.cs`, `Model.Material.cs` and `ModelExtensions.HasRenderMeshes`
  require metadata delegation when no native model exists.
- `ModelRenderer.Model` queries native mesh groups. `CreateSceneObject`,
  `UpdateObject`, scene-object model/material overrides, transform propagation
  and component disable/delete assume native model presentation. They need a
  separate owned GPU instance path with existing component behavior preserved.
- `SceneObject.Model` is native-handle based. A managed glTF scene object must
  not route through that setter or fabricate a model handle merely to satisfy it.
- The tests release temporary native handles obtained for diagnostics, preserve
  user-owned vmdl resources and clean up only test-owned mounts/files/models.

## Compiled representation discovery: required, unresolved

Source audit found:

1. `Resource.FixPath` strips `_c`; it does not map logical `.gltf` to `.glb`.
2. `GltfModelLoader.Load` only performs a cold-load fallback from a requested
   missing `.glb` to the corresponding `.glb_c`. Missing logical `.gltf` is not
   mapped to a packaged compiled artifact.
3. `Sandbox.Gltf.GltfCompiler.Compile` returns a losslessly packaged GLB byte
   array; it does not register an AssetSystem compiler or source/output identity.
4. Existing corpus/SboxBuild harnesses explicitly write `model.glb_c`, so their
   direct artifact loads do not prove application serialization/build discovery.
5. `Editor.AssetSystem.TryManagedCompile` selects registered ResourceCompiler
   identity attributes. No glTF-specific managed AssetSystem compiler was found
   in the audited Tools Assets sources. `Asset.GetCompiledFile` on NativeAsset
   delegates to native asset metadata. `AssetType.ResolveFromPath` only strips
   `_c` from the extension. Live asset-type metadata remains to be checked.

Do not invent an ad hoc naming rule in these tests. Actual compiler/resource
publication must provide the mapping; test it through that established resolver.
The required build/package acceptance matrix is:

| Case | Required assertion |
|---|---|
| Logical `.gltf` source identity | After compiling, packaging, clearing the model cache and removing the test-owned source from the package, original serialized `.gltf` identity cold-loads its valid optimized `.glb_c`. |
| Logical `.glb` source identity | Same cold-load test through original `.glb` identity; direct `.glb_c` loading alone does not pass it. |
| Both identities after save/reopen | Scene/component serialization retains each logical source identity and resolves the published artifact without authoring sources present. |
| Same-basename `.gltf` and `.glb` | Distinct assets may never silently overwrite/alias one compiled output. Audit the compiler's collision policy; require either independently correct mappings or its explicit actionable collision error. Filename policy remains a design decision until evidence exists. |
| Source/compiled coexist | Deterministic freshness/selection follows the audited engine workflow; stale compiled bytes must not silently override a changed source. |
| Compiled validity and dependencies | Published artifact bytes are a valid portable GLB, not a Source2 resource wrapper renamed `.glb_c`; every declared runtime dependency is packaged and loadable. |
| Missing/corrupt mapping | Fail clearly with the original logical path and missing/corrupt artifact context; do not quietly render an error/native fallback and report a pass. |

These package cases remain **pending positive integration tests** until the
actual mapping/publication interface is audited or implemented. The tests above
remain executable independently and cannot be used to claim these missing cases
passed. This is a required integration gap, not a deferred reduction in scope.

## Additional source audit after the worker restart

A bounded read-only audit by the identity worker found these integration points.
No editor behavior or native capability is claimed from source inspection alone.

| Surface | Observed source behavior and consequence |
|---|---|
| `Assets/NativeAsset/NativeAsset.cs:27` | Canonical `Asset.Path` replaces the source extension with the asset type's primary extension. Treating `.gltf` and `.glb` as aliases can merge same-basename logical paths. |
| `Assets/AssetSystem.cs:206-209` | Path indexes use overwrite assignment. Collision rejection must happen before publication/indexing; silent replacement is not acceptable. |
| `Assets/AssetType.cs:294-303` | `HasExtension` currently compares the primary extension, although registration also stores additional extensions. Do not infer alias support from the additional-extension list alone. |
| `Resources/ResourceLoader.cs:9-13` | Cold native-resource discovery omits `.glb_c`. Adding path loading alone does not establish BytePack hash-to-logical-path recovery. |
| `Resources/ResourceLibrary.cs:491-501` | GUID lookup is cached-only. Existing exposed native resource APIs provide path-to-GUID, but no audited cold GUID-to-path service for these raw GLBs. |
| `Model/Gltf/GltfModelLoader.cs:133-138` | Current publication clears the procedural native GUID. A persistent source identity cannot be inferred from that temporary native model. |
| `Definitions/assetsystem/IResourceCompilerContext.def` | Compiler/extension selection, native DATA/streaming blocks and child compilation are exposed. No raw root-output replacement or logical-source alias registration contract was found in the audited interface. `SetCompiler`/`SetExtension` are real hooks whose native effects still require capability evidence. |
| `Assets/AssetSystem.cs:470-483` | The existing initialization hook selects `ManagedResourceCompiler` and source extension for GameResource types. No glTF-specific equivalent is registered yet. |
| `Resources/Compiling/ResourceCompileContext.cs:65-69` | `AddGameFileReference` packages non-resource managed data. It is useful for raw GLB/sidecar bytes but does not itself resolve source identity. |
| `Utility/ProjectPublisher/PackageManifest.cs:479-500` | Equal relative paths are deduplicated without comparing payload bytes. Prevent conflicting model artifacts before they reach this stage. |

The installed `game/bin/assettypes.txt` has no glTF/GLB entries in this snapshot.
Live `AssetType` registration details and native collision behavior remain queued
for a bounded read-only coordinator query. Do not call this a native blocker
before checking supported compiler/asset override points against real behavior.

Existing `Sandbox.Gltf.GltfArtifactDependencies` supplies useful single-source
primitives: deterministic content-addressed image sidecars, raw portable GLB
rewriting, atomic artifact replacement, and dependency resolution relative to
the actual artifact. Its callers still choose the artifact path, and it does not
publish a source/GUID mapping. Reuse this implementation rather than making a
second package writer. Resolving images from the original logical source's
directory is insufficient when the compiled artifact is relocated.

Two integration directions remain candidates after that capability check:

1. Use or extend the native compiler/asset contract to publish raw artifacts and
   explicit source identities while preserving its GUID/dependency workflows.
2. Add a managed compiled-asset identity service integrated with AssetSystem,
   cold resource discovery and ProjectPublisher, preserving full source path,
   GUID, actual artifact/dependency locations and collision diagnostics.

Neither direction has been implemented or selected by this model owner. A native
parent resource may register related raw files, but wrapping the GLB in its DATA
block or substituting `.gltf` with `.glb` is not the required identity contract.
