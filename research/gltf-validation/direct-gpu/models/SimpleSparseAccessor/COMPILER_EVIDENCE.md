# Sparse compiler and input arena evidence

`CompileWithDenseAccessors` is opt-in. It preserves standard component layouts and rewrites sparse accessors only when the document has no opaque extensions or extras and the tightly packed element stride is four-byte aligned. It may expand the package; default import remains unchanged. It does not eliminate the runtime upload snapshot or arena copies generally.

Four focused source tests passed against the freshly built Debug Sandbox.Gltf assembly. The guarded installed 8fc editor test of SimpleSparseAccessor source, ordinary package and dense package passed three cases, with actual GPU position readback matching the independent source sparse-byte oracle exactly. Diagnostic capture coverage was 11843 pixels per form. External images are not embedded by the installed 7eb compiler: their URI is retained and resolved relative to the logical mounted model path. `GltfAssetImport` records external image paths for reimport invalidation in its private in-memory dependency table. The current `ProjectPublisher` code has no glTF-specific dependency inclusion found in this audit; its generic input-dependency collection is conditional on source-file inclusion. Therefore compiled-only published package inclusion and relocation of external images are unproven. A GLB with external images is valid glTF but is not a self-contained deliverable. Embedding encoded images as standard bufferViews with MIME is possible in principle, but preserving unknown extension/extras semantics, source URI identity, reimport invalidation and packaging behavior needs explicit design and tests before enabling it.

Following the ownership-policy steering, `Compile` retains external images; the separate uninstalled `CompileWithEmbeddedImages` is an explicit all-images mechanism, not the automatic policy. The corrected SboxBuild compiler-filter run passed 39/39 cases, including seven focused image cases and unchanged default URI retention. Pinned Khronos validator 2.0.0-dev.3.10 checked generated fixtures under `Temp/gltf-validation/direct-gpu/CompilerImages/validator/`: relocated BoxTextured and the PNG/JPEG data-URI case had zero errors and warnings; the preserved orphan BIN plus data-URI buffer had zero errors and one `DATA_URI_GLB` warning. The KHR_texture_basisu case had zero errors but the validator reported `UNSUPPORTED_EXTENSION`, MIME and unrecognized-format warnings, so its BasisU validation is incomplete. Actual public Model.Load of the explicit compiled-only representation has not run against an installed producer. Unknown image-level extensions are conservatively rejected by this mechanism; preserving unknown extension-owned external resources is not proven.
