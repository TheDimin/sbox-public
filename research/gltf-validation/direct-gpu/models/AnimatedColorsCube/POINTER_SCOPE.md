# Partial animation-pointer scope and evidence

The [ratified extension](https://github.com/KhronosGroup/glTF/tree/main/extensions/2.0/Khronos/KHR_animation_pointer) defines a property with a default as present when its enclosing object is present. Thus an absent `baseColorFactor` is valid under a present `pbrMetallicRoughness`; an absent parent object is not. The Object Model names `/materials/{}/pbrMetallicRoughness/baseColorFactor` as mutable `float4`. Output component conversion allows float, non-normalized integers and normalized integers before interpolation. This is a partial implementation of that one target, not a declaration of complete KHR support; optional unrecognized targets retain fallback and the required extension stays rejected.

The core [cubic interpolation definition](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#interpolation-cubic) distinguishes in/out tangents from property vertices. Signed and above-one tangents are not material-factor keys. The isolated prototype preserves spline overshoot; no specific normative post-interpolation colour clamp was found in the referenced extension/core text. The stock adapter accepts linear tint factors only in [0,1], so renderer behavior for overshoot is an explicit unresolved gate; it must not be claimed correct by silently clamping or as a parser pass.

The existing public `GltfReader.Read` binary signature is retained in the prototype; `ReadWithPartialMaterialColorAnimation` explicitly opts in. Original `UnsupportedOptionalExtensions` remains truthful. Morph override snapshots preserve the sampled colour map.

Agent-recorded isolated run: `isolated-parser-revision-observation.json`; 18 pinned model assertions plus eight synthetic checks passed. This is parser evidence only. The existing stock material rejects out-of-range `EncodeTint`; no GPU proof yet.
