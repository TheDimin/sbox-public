# ABeautifulGame optical material gap and bounded plan

The selected `screenshot.jpg` is a crop/rescale of the upstream Babylon screenshot; its transparent pawn tops are required to address the user's current material feedback. The existing 7eb public capture uses the standards-defined core fallback and displays opaque pawn tops. The glTF texture assets and original model files must remain byte-identical.

The pinned sample has two authored optical material definitions: `Pawn_Top_White` and `Pawn_Top_Black` (material indices 5 and 7), instanced by 16 node meshes. Both are core `OPAQUE` and single-sided; `KHR_materials_transmission.transmissionFactor=1` without a transmission texture; `KHR_materials_volume.thicknessFactor=0.2199999988` with no thickness texture; `attenuationColor≈(0.8,0.8,0.8)` and no `attenuationDistance`; no explicit IOR. Their base colors differ; each also uses its actual normal and metallic/roughness textures. The top and parent transforms contain no scale. Mesh-space thickness 0.22 m maps to approximately 8.6614 engine inches under the existing unit conversion, subject to the source node transform. Crucially, absent attenuation distance defaults to positive infinity: the attenuation is **neutral**, not a direct multiplication by 0.8. This authored thickness is larger than the visible sphere diameter; preserve the authored value rather than correcting it to make a particular image prettier.

`../../../../../engine/Tools/Gltf/direct-gpu/models/ABeautifulGame/test_optical_oracle.py` independently reads all three pinned source forms and checks the actual material declarations, default IOR Fresnel F0=0.04, and Beer attenuation controls for infinite, zero, one-distance and two-distance paths. It passed 3/3 Python unit cases. This is source/spec evidence, not an engine parser, shader, pixel, public loading or image match pass.

## Shared integration contract to review with material owner

- Extend the shared reader with typed transmission and volume declarations and defaults; preserve optional fallback if the capability is not enabled. Do not advertise required support until the complete selected renderer path is validated. Reject invalid finite/range/texture declarations; no silent fallback after selecting corrupt required data.
- Optical transmission is distinct from glTF alpha-as-coverage and must coexist with the actual `alphaMode`; factor/linear-red transmission texture, metallic and roughness modify the base lobe while dielectric specular reflection stays visible. Volume thickness factor and optional linear-green thickness texture, independent UV/sampler and transformed mesh-space units feed refraction. Default IOR is 1.5. Attenuation uses world-space path length and infinite default distance; avoid applying attenuationColor as a tint without a finite attenuation distance.
- Coordinate with the diffuse-transmission owner: diffuse transmission and its color mix into diffuse scattering before specular optical transmission, not as the same texture/parameter or an alpha substitute. Preserve the core base-color and normal/MR role/color-space/UV/sampler bindings and PBR factors.
- Investigate native `game/core/shaders/glass.shader` and engine framebuffer-copy/refraction services first, including sort/depth, native material attributes and IBL. Its hardcoded glass metalness, compositing modes and refraction control are not automatically a correct glTF implementation. If it cannot represent the required semantics, define the smallest supported stock-derived path with explicit limitations. Do not implement a one-model glass override as if it were the format implementation.
- Independent controls: transmission zero versus one with the same opaque coverage and same source base color; specular reflection retained against a dark background; metallic one suppresses transmission; roughness affects transmitted blur; correct default IOR and finite-distance Beer laws; no-distance neutral attenuation; texture channel and UV/sampler adversaries; single/double-sided volume behavior and depth/compositing. Test a background landmark through a closed volume, normal/roughness response and scene-native empty/deletion controls. Both sample pawn materials and an explicit wrong-tint/wrong-alpha control must be visibly distinguished. Validate source and current one canonical compiled representation under the actual public `Model.Load`/`ModelRenderer`, not a helper override or substituted material.

The user's requested 90% appearance threshold is a human review target. No generated screenshot, source-data test, or numerical test may be called an accepted visual match until the user reviews it. The ACES/HDRI/camera reconstruction and this optical feature are separate gates.

Primary specs: [KHR_materials_transmission](https://github.com/KhronosGroup/glTF/tree/main/extensions/2.0/Khronos/KHR_materials_transmission), [KHR_materials_volume](https://github.com/KhronosGroup/glTF/tree/main/extensions/2.0/Khronos/KHR_materials_volume). Khronos glTF 2.0.1 registry baseline remains recorded in the project contract.

## Native framebuffer-copy diagnostic

On producer e05, the actual canonical public model with temporary stock-glass overrides on material slots 5 and 7 passed a 1/1 native scene diagnostic. Stock glass declares `bWantsFBCopyTexture=1`, but the custom object's initial flag was false. With the flag off, 67 translucent callbacks saw no framebuffer copy; with the flag explicitly enabled, 67/67 saw a valid copy and 2,415 pixels changed in the target sphere region (9,227 globally). Scene object invalidation, stopped drawing, and an independently uniform deletion frame passed. Receipt: `Temp/gltf-validation/direct-gpu/beautiful-e05-native-glass-route/probe-01-editor_direct_gpu_tests/receipt-01.json`, SHA-256 `c18e004af3f58dd64f197641c73c8c16e7c000264538204e068c53019bbd9313`. This establishes a native resource route and a missing automatic flag; temporary stock glass, its diagnostic refraction value 1.05, and the changed pixels do not implement or validate the glTF optical model.

`framebuffer-classification-proposal.patch` is an isolated candidate to aggregate the copy requirement across currently effective translucent materials, including material overrides and variant binding. `../../../../../engine/Tools/Gltf/direct-gpu/models/ABeautifulGame/FramebufferClassificationTests.cs` proposes positive/negative override transitions, a rejected invalid update, actual copy exposure and cleanup; it requires an installed candidate and is not yet run. Variant and material-switch rollback controls and Alpha's independently sorted scene objects also require integration validation. No required-extension capability should be advertised on the strength of this framebuffer fix alone.
