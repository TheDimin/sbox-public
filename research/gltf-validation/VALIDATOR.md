# Khronos validator adapter

`../../engine/Tools/Gltf/scripts/validator_adapter.py` runs the official Khronos glTF-Validator CLI against a freshly checked pinned sample checkout and, optionally, the corresponding generated `.glb_c` artifacts. It is independent of the s&box readers. It preserves every reported validator message, the source or artifact hash and source external-resource hashes. It does not waive defects or infer rendering correctness. The existing `../../engine/Tools/Gltf/scripts/validate.py` full-goal gate remains unchanged.

The recorded Linux x64 tool is Khronos release [2.0.0-dev.3.10](https://github.com/KhronosGroup/glTF-Validator/releases/tag/2.0.0-dev.3.10), source commit [bcd52cc4ba5f333b2999a58f67cc05ddf28b4fb1](https://github.com/KhronosGroup/glTF-Validator/commit/bcd52cc4ba5f333b2999a58f67cc05ddf28b4fb1). The release archive `gltf_validator-2.0.0-dev.3.10-linux64.tar.xz` observed SHA-256 is `168eba887964125abe17ae97899b38d0b3cfd73c266c78424c194929ddcbc522`, and its executable SHA-256 is `5cba1e097935c9efd929d24a49610824259b030f0ae45672273bfbcbb5b87a62`. Khronos's release metadata did not publish a digest; these hashes record the copy observed from the official release and are not an upstream signature or independent attestation. Review the origin and hashes before changing the pin. Keep the release `LICENSE` and `NOTICES` with redistributed copies; generated binaries and model artifacts belong in ignored `Temp/`, not Git.

```sh
python3 -B -m unittest discover -s research/gltf-validation -p 'test_*.py' -v
python3 -B engine/Tools/Gltf/scripts/validator_adapter.py \
  --validator Temp/gltf-validation/validator/gltf_validator \
  --corpus Temp/gltf-reference/glTF-Sample-Assets \
  --compiled-root Temp/gltf-validation/compiled \
  --compiler-report Temp/gltf-validation/compiled.json \
  --output Temp/gltf-validation/khronos-validator.json
```

Omit `--compiled-root` for source-only validation. Compiled validation requires a `--compiler-report` from a compile-enabled scanner run for freshness: its corpus revision, per-case scope, successful managed round trip, source hash, artifact hash and exact packaged-dependency hash map must match the current source and files. The map uses paths relative to the model's package directory, and must be present even when empty. A missing, failed, mismatched or omitted case is incomplete even if an older file still exists. The receipt is hashed and checked for changes during the run. Supplying `--compiled-root` without `--compiler-report` is allowed for diagnosis, but every compiled result is labeled `not-provided` for freshness and the compiled pass fields remain false. The receipt is evidence, not cryptographic proof of who produced it.

Use `--case Box/` for a diagnostic subset; a subset can report selected cases passing, but never sets the all-source/all-compiled fields to true. Exit status 0 means the selected applicable cases pass the requested validator checks with required freshness, 1 means invalid, incomplete or missing applicable results, and 2 means setup failed. The complete goal remains false even when exit status is 0. The checkout must match the `coverage.json` corpus pin and be clean before and after the run. Out-of-scope variants remain in the report with all their issues, but do not count as supported.

The pinned official validator does **not** support every selected extension. An `UNSUPPORTED_EXTENSION` message or a truncated issue list marks a case `incomplete`, even when the CLI exits 0. A reported validation error marks it `invalid`; warnings and informational messages are retained. Missing compiled files, an absent or hash-mismatched validator, malformed reports, mismatches between process exit and error counts, and inventory errors never pass. No automatic defect waivers are applied. The release's [feature list and CLI behavior](https://github.com/KhronosGroup/glTF-Validator/tree/2.0.0-dev.3.10#implemented-features) document the validator's scope.

The CLI rejects the `.glb_c` suffix. For each compiled artifact the runner creates a temporary `.glb` copy **in the artifact's own directory**, validates that copy with resource validation enabled and removes only that temporary copy. Thus external URI resolution tests the generated artifact's location rather than silently resolving against the original corpus. Declared local dependencies must resolve inside the supplied compiled root; the runner hashes present dependencies before and after validation, recording missing, escaping or changing resources. A successful structural check still does not establish optimized GPU layout, dependency packaging beyond validator checks, visual equivalence, runtime behavior or performance. Report output cannot be placed inside either input tree or overwrite the validator.

The report records input hashes and the validator binary hash, but these do not authenticate a hostile executable or replace review of the tool distribution, its dependencies or the validation environment. Before integrating this adapter into a completion gate, review the checked-in runner, attest the trusted executable and run environment, add required independent extension decoders and visual/runtime evidence, and decide an explicit review process for genuine upstream asset defects.
